# IDA fixup audit notes

The prelude supplies the scalar aliases, SIMD vector types, libc structure layouts, and opaque handles which IDA names without emitting definitions. The layouts are the normal x86-64 GNU/Linux layouts needed by recovered member accesses, including the public-size glibc pthread unions, the private `FILE` tail fields IDA exposes, and the overlaid `sigaction` handler forms; compact opaque definitions are used where the function only passes an object through. IDA width names such as `_BYTE`, `_QWORD`, and `_OWORD` map directly to C integer types of the same width.

IDA helper syntax is represented with equivalent GNU C operations. Partial-register helpers, including all byte lanes through `BYTE15`, use address-based lvalues; variadic helpers use compiler builtins, segment-register reads keep their intrinsic declarations, and Intel SIMD helper names receive declarations with results selected from the name suffix. IDA's MS-style SIMD lane members are rewritten as indexed views of the same vector storage; scalar zero initialization, time-structure loads, and `_OWORD` copies use explicit same-width GNU vector/integer views.

Syntax normalization removes only decompiler artifacts: anonymous DWARF type spellings become width-compatible placeholder types, transparent-union implementation members become their underlying scalar, and misleading recovered `const` qualifiers are relaxed where IDA itself emits stores. A leading C++ `::name` is preserved as a distinct C identifier with an assembler label for the original global symbol, avoiding collision with same-named locals. Lost `FILE *` types are restored at member accesses with an explicit cast, and IDA's `new_base + old_pointer - old_base` spelling becomes explicit byte-address rebasing.

Library declarations are emitted only when referenced. Exact prototypes cover common allocation, string, stdio, file, identity, localization, and division routines so GCC preserves pointer widths, aggregate returns, variadic calling rules, and argument conversions. Unknown external functions otherwise retain old-style parameter lists because IDA's recovered call sites often disagree, while known return types are preserved.

Sibling declarations are derived solely from `ctx.siblings`. Called sibling names are looked up in a per-binary cache, their recovered return type is retained, and their arguments use an old-style declaration to tolerate inconsistent parameter recovery without imposing a guessed ABI. Immediately dereferenced calls receive a pointer result only when they are neither a target nor a known sibling definition.

IDA's address-derived global names are declared according to their encoded width and use: scalar, indexed storage, advancing byte pointer, pointer table, function pointer, or a structure selected by observed members. `xmmword_` data is represented as integer `_OWORD` storage because IDA uses these labels for both integer arithmetic and vector loads; intrinsic accesses retain explicit vector pointer casts. Untyped `stru_` objects copied with IDA's vectorized `timespec`/`timeval` idiom retain that aggregate type through simple assignments.

Other missing symbols are handled by the repair pass, which parses GCC diagnostics and inserts conservative externs or type aliases ahead of the target body; it recognizes signal-set API uses, indexed pointer results, and structure members while avoiding redeclarations and diagnostics cascading from malformed local declarations. String and character literals are excluded from identifier-use inference so their prose cannot turn a data symbol into a false function declaration. If GCC identifies a contradictory recursive arity recovered by IDA, only that call expression is cast to an old-style function pointer with the original return type. GCC-rejected mixed pointer subtraction and pointer bit masks are repaired only at the reported source line by making IDA's byte-address operation explicit; the emitted operands and control flow remain unchanged.
