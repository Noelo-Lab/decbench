Kuna scalar types and helper operations: kuna names integer storage types by byte width (`int4`, `uint8`, and `undefinedN`) and emits `CONCAT`, `SUB`, extension, carry/borrow, and `FLOAT_ROUND` pseudo-operations. The prelude maps ordinary widths to the corresponding C scalar, represents 16-byte values with `__int128`, reconstructs the 10-byte floating representation with a union, and lowers helpers to shifts, exact byte loads, or compiler overflow builtins. High-word extraction from an x87 value copies its upper two stored bytes instead of illegally shifting `long double`; diagnostic-only `-Wno-*` flags suppress expected warnings without changing optimization.

Library declarations: `prepare` includes a standard header only when one of its symbols occurs and suppresses a header when the target itself has that library name. This supplies ABI-correct return and argument types for libc/POSIX operations, including pointer-returning and no-return functions, while avoiding conflicts with kuna's inferred target signatures.

Sibling and inferred prototypes: referenced functions present in `ctx.siblings` receive the signature kuna emitted; inconsistent ordinary `void` signatures are left old-style unless kuna marks the call no-return. Pointer return types are inferred from explicit pointer casts or assignments in the target and its siblings, and kuna's `// no-return` call annotation becomes a `noreturn` declaration so gcc can preserve terminal control flow. When kuna indexes from a sibling function symbol as an address, the index is made explicit as byte arithmetic on that code address.

Callbacks and pointer casts: kuna often types callbacks as `void *` and then invokes them. Those call sites are cast to an unprototyped function pointer, retaining the recovered arguments and machine-level calling sequence. A pointer converted directly to floating point is first converted to `long`, matching the numeric address conversion expressed by kuna while making it valid C.

Byte slices and aggregates: kuna writes Ghidra-style pieces such as `v._8_8_`, array-looking scalar casts, and returned aggregates assigned directly to byte arrays. Native-size pieces and direct 1/2/4/8-byte array assignments become typed scalar lvalues; odd sizes use exact-width builtin copies. Sixteen-byte assignments, pointer-to-array stores, and bitwise uses become `__int128` operations, while array casts become same-width unsigned casts. A slice used both as a pointer and as an explicitly numeric arithmetic operand retains the cast at that numeric use. Standard two-word struct returns such as `imaxdiv_t` are copied into raw 16-byte slots without changing their bits.

Wide vectors: assigned 32- and 64-byte array temporaries and 32/64-byte pseudo-fields become GNU byte-vector types. Kuna's AVX compare, byte subtraction, zero-extension, half extraction, sum-of-absolute-differences, and word extraction helpers map to vector operations or exact byte loops. Its O0 128-bit byte/dword/qword insertion, byte shuffle, and low-lane unpack helpers map to raw `__int128` lane operations with addressable intermediate values; 0/1 selection arithmetic reads a 16-byte array's stored bit pattern rather than its decayed address.

Recovered register views: kuna sometimes applies a scalar cast to the left side of a compound assignment to describe a register subpiece. The fixup lowers this to an explicit operation, truncation to the cast type, and assignment back to the original temporary. Integer temporaries that receive a call result and are subsequently dereferenced get an explicit pointer-sized load; a direct `*(integer_type)address` form becomes the corresponding pointer cast, retaining kuna's address-valued integer representation.

Void pointers and standard streams: a dereference of `void *` is typed from the adjacent scalar cast or `CONCAT28` value that kuna emitted. Switches over recovered function pointers compare their integer addresses. Direct `stdin`, `stdout`, or `stderr` flag tests load the stream's first unsigned word explicitly, matching kuna's field access while avoiding arithmetic on the C `FILE` aggregate.

Globals and external objects: free identifiers outside kuna's regular `aN` argument and `vN` local namespaces receive external declarations. Calls observed elsewhere distinguish functions from objects, while complete direct assignments, comparisons, floating products, explicit casts, bitwise constants, standard-stream uses, and true unary dereferences propagate supported types. Pointer-to-array casts retain their exact shape; indexed objects otherwise remain arrays unless kuna assigns the object itself. Cached sibling evidence is used only when stronger current-function evidence is absent.

Diagnostic repair: after a failed compile, undeclared identifiers receive conservative declarations based on use. Calls whose emitted arity disagrees with a system, sibling, or recursive target prototype are made through an old-style function pointer with the same return ABI, retaining every argument. For gcc-reported pointer/integer arithmetic, only pointer operands on the failing RHS are cast to machine-word addresses; their declarations and dereference uses remain unchanged. Invalid scalar-cast dereferences receive the equivalent pointer cast on retry. Conflicting system declarations are isolated without deleting expressions or statements.
